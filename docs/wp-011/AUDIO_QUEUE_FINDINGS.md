# WP-011 Technical Findings — Pre-Podcast Buffering, Paced Sequential TTS & Rate-Limit Recovery

## 1. Root Cause of Intermittent Unavailability
- **Why turns failed intermittently:** The earlier WP-011 queue entered active playback immediately with `MAX_TTS_CONCURRENCY = 2` and zero inter-request spacing, colliding with Google free-tier rolling Gemini TTS RPM/RPD quota bursts and tripping a premature session-wide outage after `2` capacity failures. Maya appeared frequently simply because the explainer role carries multiple later turns generated after earlier concurrent bursts had consumed quota headroom.
- **UI/state gaps fixed:** Silent timed turns previously displayed `Speaking` / `● ON AIR`, `CaptionPanel` showed stale `"Audio unavailable — showing caption"` on recovered clips, and `replay()` did not reset eligible transient failures.

## 2. Initial Buffer Strategy, Sequential Concurrency & 1,500 ms Pacing
- **Locked defaults (`src/lib/tts/tts-pacing-config.ts`):**
  - `MAX_TTS_CONCURRENCY = 1` (strictly one active `POST /api/tts` request at a time; never > 1 in production queue).
  - `MIN_TTS_REQUEST_INTERVAL_MS = 1_500` (`KURO_TTS_REQUEST_INTERVAL_MS` server-validated/clamped `[1000, 5000]` ms, fallback `1500` ms, never via `NEXT_PUBLIC_*`, passed numerically from [src/app/page.tsx](../../src/app/page.tsx)).
  - `INITIAL_AUDIO_BUFFER_SIZE = 2` (`1` for a 1-segment episode), `PREFETCH_LOOKAHEAD = 2`, `MAX_AUTOMATIC_CAPACITY_RETRIES_PER_SEGMENT = 1`, cooldown clamp `[1000, 30000]` ms (default `8000` ms).
- **Pre-podcast preparation (`AudioPreparationStatus`):** Script generation transitions into [AudioPreparationPanel](../../src/components/kuro/player/audio-preparation-panel.tsx) (`idle | preparing | ready | partial | cooldown | unavailable | cancelled`). Turns `1` and `2` generate sequentially (`verifyPlayable` decode-checked) while `PodcastStage` stays idle in `PREPARING`. **`Start podcast`** enables only after opening clips decode playable (`Start podcast` gesture begins Turn `1` from cache and wakes Turn `3` generation after the pacing interval).
- **Partial-buffer & failure rules:** If Turn `1` succeeds and Turn `2` hits `429`, preparation pauses with `"One voice is ready. Waiting briefly for the next turn."`, retries once after `Retry-After`, and if exhausted offers **`Start with captions and available audio`**. Permanent missing-key/auth errors stop immediately with **`Continue with timed captions`** and **`Return to form`**.
- **One authoritative scheduler:** All requests (preparation, background lookahead `[currentIndex .. currentIndex + 2]`, Replay, and manual **`Retry voice`**) share one `pacingTimer` + `cooldownTimer`. Client validation rejections (`INVALID_TTS_INPUT`) and cache hits are never paced.

## 3. Non-Fatal 429 Handling & Hosted vs. Timed Display Correction
- **HTTP `429` (`TTS_RATE_LIMITED`):** Enforces shared `Retry-After` (overrides the `1,500 ms` interval), keeps cached audio playing, shows `"Voice generation is briefly paused"` with countdown `"Preparing more voices in Xs."`, retries the segment once, and on second `429` falls back for *that turn only* — **never terminating later segments in the hosted session** solely due to `429`s.
- **Permanent shutdown:** Stops immediately (`0` retries) for missing API key (`TTS_NOT_CONFIGURED`), auth `401`/`403`, unsupported TTS model (`TTS_PROVIDER_UNAVAILABLE` non-retryable), and `>= 2` consecutive non-429 internal/provider/audio errors (`safety` & invalid input remain non-retryable per segment).
- **Display correction ([podcast-stage.tsx](../../src/components/kuro/player/podcast-stage.tsx), [kuromate-host.tsx](../../src/components/kuro/player/kuromate-host.tsx)):** Silent timed fallback renders **`TIMED CAPTIONS`** and Kuromate **`Captioning`** (static posture, amber mic LED, no waveform/Speaking/ON AIR). `CaptionPanel` clears `"Audio unavailable — showing caption"` as soon as a segment has cached/recovered audio.

## 4. Exact Provider-Call Bounds & Lifecycle Cleanup
- **Per segment (automatic):** Up to `2` client attempts (`1` initial + `1` post-cooldown retry); typical `3` upstream provider calls (`1` capacity fail + `1` post-cooldown retry with max `1` server empty-audio regen), absolute ceiling `4` (`2 × 2`).
- **Quick episode (8 turns):** `8` ideal client calls -> `16` max automatic client calls -> `24` typical / `32` ceiling automatic upstream calls (and fewer when lookahead pauses on outages).
- **Detailed episode (15 turns):** `15` ideal client calls -> `30` max automatic client calls -> `45` typical / `60` ceiling automatic upstream calls.
- **Manual `Retry voice`:** Bounded by `MAX_MANUAL_RETRIES_PER_SEGMENT_PER_CYCLE = 1` (`1` client request, `1–2` upstream calls), resets only on a new episode or Replay cycle after cooldown, cannot bypass `1,500 ms` pacing or cooldown, deduplicates rapid clicks, preserves cache, and clears audio-unavailable notices on recovery.
- **Replay retries:** `0` refetches for cached clips (`hasCachedAudio`); transiently failed clips reset once per Replay cycle up to `2` automatic client calls (`1 + 1`) sequentially.
- **Cleanup:** `createEpisodeObjectUrlPool` revokes every blob URL **exactly once** across replace/decode failure/unmount; `cancelPreparation()`, episode switches, `completeEpisode()`, and `dispose()` clear `pacingTimer`, `cooldownTimer`, fallback/reaction timers, and abort controllers.
